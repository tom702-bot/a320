# Qantas A321P2F project guide

Keep manuals private. Never commit, upload or publish the PDFs, full extracted page text or images of original manual pages. The user explicitly chose local file loading. Render and search them only on the user’s device through private-manuals.mjs. Public data contains authored study material and source navigation metadata only.

Preserve the supplied manuals exactly. Use the source set in data/manuals.json and retain page effectivity, conditions and exact references. Never relabel a different aircraft or engine source as evidence for this one. New questions require matching original PDF pages and source hash. Do not claim the supplied revision is the latest controlled revision. Original manufacturer wording inside manuals must not be rewritten for branding.

Keep everything under one A321P2F banner with no registration selector or registration-based study filter. Retain equipment/procedure differences as inline notes and preserve original source effectivity. Keep the three entry pages identical. Update sw.js when the app changes. Keep quizzes specific to the supplied Qantas A321P2F source set. Preserve the illustrative systems models; their geometry and injected failure responses are not operational certification. Keep crew roles as printed, avoid treating PF/PM as a fixed seat assignment, and retain all conditional gates. Communications are omitted from selected recall drills; source procedures remain complete.

Keep new aircraft study progress separate from previous source sets. Never award a completed exam result to an incomplete run. Run node validate-trainer.js and node test-trainer.js before publishing. Do not restore superseded training data from Git history without a new source review.
